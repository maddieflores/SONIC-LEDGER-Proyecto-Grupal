# SONIC LEDGER — DOCUMENTACIÓN TÉCNICA
## CU11 — Registrar y consultar historial de reproducción

### 1. Resumen Ejecutivo
Se implementó de manera completa y transversal el caso de uso **CU11 — Registrar y consultar historial de reproducción** en la plataforma Sonic Ledger, cerrando satisfactoriamente el **Sprint 1**. La solución abarca:
- **Backend:** NestJS + TypeORM + PostgreSQL (con migración incremental, deduplicación idempotente y resolución híbrida de pistas `LOCAL` y `AUDIUS`).
- **Capa Compartida (`shared`):** Modelos de datos, tipos TypeScript, lógica centralizada de umbrales y cliente HTTP para persistencia de eventos.
- **Frontend Web:** React 19 + TypeScript + Vite (integración en el reproductor persistente CU08 con rastreo de tiempo neto, pestaña "Historial" en Mi música, filtros y reactivación del sidebar).
- **Móvil Android:** React Native 0.88 + Expo 58 (rastreo en `NativePlayerProvider`, pestaña "Historial" en `mi-musica.tsx`, filtros, eliminación puntual y limpieza general).

Todo el flujo respeta estrictamente la reproducción ininterrumpida de CU08 durante la navegación y no almacena archivos de audio ni registros ficticios para canciones externas provenientes de Audius.

### 2. Base de Datos y Persistencia

#### Migración incremental
- **Archivo:** `backend/src/migrations/1794489000000-ListeningHistory.ts`
- **Tabla creada:** `listening_history`
  - `id`: `UUID` (Primary Key con `gen_random_uuid()`).
  - `usuario_id`: `UUID` (Foreign Key a `usuarios(id)`, `ON DELETE CASCADE`).
  - `track_id`: `varchar(100)` NOT NULL (identificador UUID de pista local o ID de Audius).
  - `source`: `varchar(20)` NOT NULL (`LOCAL` | `AUDIUS`).
  - `client_event_id`: `varchar(150)` NULL (identificador de sesión de cliente para deduplicación idempotente).
  - `event_type`: `varchar(20)` NOT NULL (`PLAYED` | `SKIPPED`).
  - `listened_seconds`: `double precision` NOT NULL DEFAULT 0.
  - `track_duration_seconds`: `double precision` NULL.
  - `started_at`: `timestamptz` NOT NULL.
  - `ended_at`: `timestamptz` NULL.
  - `created_at`: `timestamptz` NOT NULL DEFAULT now().

#### Índices y Restricciones
1. `IDX_listening_history_usuario_created`: `(usuario_id, created_at DESC)` para acelerar consultas paginadas y filtradas del historial cronológico de cada usuario.
2. `IDX_listening_history_user_client_event`: `(usuario_id, client_event_id)` para garantizar deduplicación rápida e idempotencia sin colisionar entre usuarios distintos.

### 3. Backend (NestJS + TypeORM)

#### Módulo y Entidad
- `backend/src/history/listening-history.entity.ts`: Entidad TypeORM `ListeningHistory` con relaciones ManyToOne hacia `Usuario`.
- `backend/src/history/history.module.ts`: Importa `TypeOrmModule.forFeature([ListeningHistory, Cancion])` y `LibraryModule` para resolución polimórfica de pistas. Registrado en `backend/src/app.module.ts` y `backend/src/data-source.ts`.

#### Regla de Negocio Centralizada (`backend/src/history/playback-rule.ts`)
- **Umbral de reproducción válida (`PLAYED`):**
  - Mínimo **30 segundos** de audio real escuchado para canciones de duración normal o desconocida.
  - Al menos el **50 %** de la duración total para canciones cortas (< 30 segundos).
- **Omisión (`SKIPPED`):**
  - Registrado si el usuario cambia de canción o detiene la reproducción antes de alcanzar el umbral de reproducción válida (filtrando clics accidentales de menos de 2 segundos).
- **Funciones exportadas:**
  - `isValidPlayback(listenedSeconds, durationSeconds)`: Evaluación booleana del umbral.
  - `determineEventType(listenedSeconds, durationSeconds)`: Retorna `'PLAYED' | 'SKIPPED'`.

#### DTOs y Validación (`backend/src/history/history.dto.ts`)
- `RecordPlaybackEventDto`:
  - `trackId`: string no vacío.
  - `source`: `'LOCAL' | 'AUDIUS'`.
  - `listenedSeconds`: número >= 0.
  - `trackDurationSeconds`: número opcional >= 0.
  - `clientEventId`: string opcional (máx 150 caracteres).
  - `startedAt`: fecha ISO 8601 opcional.
  - `endedAt`: fecha ISO 8601 opcional.
  - `eventType`: opcional `'PLAYED' | 'SKIPPED'`.
- `GetHistoryDto`:
  - `page`: número opcional >= 1 (por defecto 1).
  - `pageSize`: número opcional 1–100 (por defecto 20).
  - `eventType`: opcional `'PLAYED' | 'SKIPPED' | 'ALL'`.

#### Servicio (`backend/src/history/history.service.ts`)
- `recordEvent(userId, dto)`:
  - Recupera la duración real de la pista desde la entidad local o catálogo si no vino en el DTO.
  - Evalúa la regla centralizada para clasificar el evento como `PLAYED` o `SKIPPED`.
  - Implementa idempotencia: si ya existe un evento para el mismo `clientEventId` y usuario, actualiza el tiempo y estado sin duplicar filas.
- `getHistory(userId, query)`:
  - Consulta paginada con orden descendente por fecha.
  - Aplica filtro por `eventType` si se solicita.
  - Resuelve metadatos completos y enriquecidos de las pistas delegando a `LibraryService.resolveTracks` (resolviendo artistas locales o externos de Audius de forma unificada).
- `getRecent(userId, limit)`:
  - Retorna las últimas pistas únicas reproducidas para widgets y vistas rápidas.
- `deleteEntry(userId, id)`:
  - Elimina una entrada puntual asegurando la pertenencia al usuario autenticado.
- `clearHistory(userId)`:
  - Vacía la totalidad del historial de reproducción del usuario.

#### Controlador (`backend/src/history/history.controller.ts`)
Bajo la ruta `/api/auth/history` protegida por `JwtGuard`:
- `POST /api/auth/history/events`: Registra un evento de escucha (idempotente).
- `GET /api/auth/history`: Lista el historial paginado (`page`, `pageSize`, `eventType`).
- `GET /api/auth/history/recent`: Lista las canciones más recientes.
- `DELETE /api/auth/history/:id`: Elimina un registro puntual.
- `DELETE /api/auth/history`: Vacía todo el historial del usuario.

#### Pruebas Unitarias Backend
- Archivo: `backend/src/history/history.spec.ts` (8 pruebas automatizadas cubriendo umbrales de 30s/50%, omisiones, deduplicación por `clientEventId`, resolución polimórfica, borrado puntual y limpieza total).
- Suite global backend: **13/13 archivos de prueba aprobados, 59/59 pruebas unitarias exitosas**.

### 5. Frontend Web (React + TypeScript + Vite)

#### Rastreo en Reproductor Persistente (`frontend/src/Playback.tsx`)
- Se incorporó `sessionRef` con estado de sesión: `songId`, `source`, `sessionId`, `startedAt`, `lastPosition`, `listenedSeconds`, `duration` y `playedSent`.
- **Detección de tiempo real:**
  - En `onTimeUpdate`: se calcula `delta = currentTime - lastPosition`. Si `0 < delta < 2`, se incrementa `listenedSeconds`. Se descartan saltos manuales (seeks) y períodos en pausa.
  - Al cruzar el umbral centralizado (`isValidPlayback`), despacha automáticamente el evento `PLAYED` una única vez por sesión.
  - Al cambiar de canción en `begin()`, detener con `stop()` o desmontar: si no se envió `PLAYED` y el tiempo escuchado es >= 2 segundos, despacha un evento `SKIPPED`.
- **Navegación protegida:** Se actualizó la expresión regular de rutas autorizadas para incluir `/historial`, `/mi-musica`, `/playlists`, `/favoritos` y `/lanzamientos`, garantizando que la reproducción de CU08 nunca se detenga al explorar la biblioteca o el historial.

#### Vistas e Integración UI (`frontend/src/UserLibrary.tsx` y `frontend/src/ArtistReleases.tsx`)
- Pestaña **"Historial"** dentro de `UserLibrary.tsx` con conteo de elementos.
- Filtros interactivos por tipo de evento: `Todas`, `Reproducidas` y `Omitidas`.
- Filas de historial compactas con:
  - Portada de la canción.
  - Título, artista y etiqueta de origen (`LOCAL` o `AUDIUS`).
  - Badge visual de evento: Cyan para `Reproducida`, Ámbar para `Omitida`.
  - Duración escuchada en segundos y marca de tiempo formateada.
  - Botón de reproducción inmediata delegando a CU08 (`playback.play`).
  - Botón para eliminar entrada puntual.
  - Botón "Limpiar historial" con confirmación de diálogo.
- Activación del enlace **"Historial"** en la barra lateral de navegación tanto en la biblioteca como en las vistas de lanzamientos artísticos (`ArtistReleases.tsx`).
- Ruta agregada: `/historial` en `frontend/src/App.tsx`.

### 8. Decisiones Técnicas y Cierre del Sprint 1

1. **Idempotencia contra duplicación:** El identificador `clientEventId` generado por sesión en web y móvil previene que re-renders de React o aperturas del minirreproductor generen múltiples filas en base de datos.
2. **Sin persistencia externa:** Las pistas de Audius se registran en `listening_history` exclusivamente mediante su `track_id` y `source: 'AUDIUS'`, resolviéndose al vuelo mediante el servicio de descubrimiento sin saturar el almacenamiento de audio local.
3. **Persistencia ininterrumpida de CU08:** Se armonizaron las expresiones regulares de control de rutas en frontend web y Android, asegurando una experiencia de audio fluida en segundo plano durante la exploración de playlists, favoritos, lanzamientos e historial.
