# CU07 — Explorar, buscar y consultar catálogo musical

Implementado en web React/TypeScript y móvil React Native/Expo. Tras identificar que CU05 solo tenía API privada para artistas, el usuario autorizó expresamente añadir el contrato de lectura del catálogo publicado. No se añadieron endpoints de escritura, migraciones ni datos de ejemplo.

## API implementada con autorización del usuario

Todas las rutas requieren una sesión existente (cookie HttpOnly web o token Bearer móvil). Se permite consultar a CLIENTE y a las demás cuentas autenticadas. La lectura no exige ser propietario de una canción publicada.

| Método | Ruta | Resultado |
|---|---|---|
| GET | `/api/auth/catalog` | Canciones publicadas, búsqueda/filtro y paginación real |
| GET | `/api/auth/catalog/genres` | Géneros activos presentes en publicaciones reales |
| GET | `/api/auth/catalog/:id` | Detalle publicado y hasta cuatro publicaciones adicionales del mismo artista |
| GET | `/api/auth/catalog/:id/cover` | Portada de una publicación, con autenticación y comprobación de visibilidad |

Listado: `q` busca por título, nombre artístico y nombre del género; `generoId` combina búsqueda con género; `page` y `pageSize` paginan en servidor (máximo 50, interfaz 12). Se rechazan parámetros desconocidos, ids inválidos y paginación fuera de rango. Las coincidencias utilizan parámetros de consulta y escapan comodines introducidos como texto.

Respuesta: `items`, `total`, `page`, `pageSize`, `totalPages`. Cada canción expone únicamente `id`, `titulo`, artista (`id`, `nombre`), género (`id`, `nombre`) o null, `duracionSegundos`, `descripcion` y `coverUrl` del catálogo o null. No expone rutas de audio privadas, ids de usuario, emails ni roles.

Listado, detalle, publicaciones relacionadas y portadas verifican `estado = publicado` en PostgreSQL. Un id de borrador enviado manualmente devuelve 404 también al solicitar portada. Sin autenticación se devuelve 401. La administración de CU05 y sus archivos privados siguen exigiendo ARTISTA/propietario; CLIENTE continúa recibiendo 403 en esas rutas.

Las portadas se resuelven solo desde referencias locales canónicas creadas por CU05, con nombre UUID y extensión PNG/JPG. No se aceptan rutas arbitrarias ni URLs remotas. Una referencia de portada externa/no compatible se representa como null y la interfaz muestra un marcador musical neutro. No hay acceso a audio desde el contrato CU07.

No se modificó el esquema ni se insertaron canciones. Los contadores y resultados proceden íntegramente de la base existente, incluidos los registros locales de pruebas que ya estuvieran publicados.

## Pantallas y comportamiento

- Explorar: hero con retrato musical existente, buscador, géneros reales, contador y lista compacta.
- Buscar: estado de Explorar con consulta visible, limpiar, encabezado Resultados y mismo componente de canción. Sin pestañas de artistas/álbumes que no puedan devolver esos tipos.
- Detalle: volver, portada grande, título, artista, género y duración. Descripción y sección Más de este artista solo cuando existen datos.
- Carga, error con reintento, catálogo vacío, ninguna coincidencia, ausencia de portada y canción no disponible.
- La búsqueda usa 250 ms de espera y AbortController. Al cambiar consulta, género o página se cancelan las solicitudes anteriores y se descartan sus respuestas. El contador proviene del total de servidor, no de filtrar una página local.
- Web conserva consulta/filtros/página en parámetros URL. Móvil mantiene ese estado en la pantalla al volver del detalle.
- Native usa FlatList, Safe Area y componentes táctiles. El botón de búsqueda enfoca el campo. Favoritos permanece deshabilitado; los accesos Inicio/Perfil apuntan a rutas existentes.
- Las portadas móviles son de 60 unidades, o 52 en pantallas estrechas; textos de título/artista 16/13, elipsis, duración tabular y play visual de 38 con área táctil de 44. Web usa portadas de 60/52, filas de aproximadamente 84 px y columnas alineadas.
- El play está deshabilitado e identificado como Reproducción próximamente. La portada y el título son la acción diferenciada de detalle. No existe reproducción simulada ni cambio a pausa.
- No se añadieron métricas ficticias, marcas registradas, marcos de teléfono ni hora/batería dibujadas. Los iconos nativos se construyeron con Views y bordes; no se usaron emojis.

## Cómo visualizar

Web: API en puerto 3000, `npm run dev:frontend` y abrir `http://localhost:5173/explorar`. Iniciar sesión con una cuenta existente. El detalle está en `/explorar/cancion/:id`.

Móvil: configurar `EXPO_PUBLIC_API_URL` en `mobile/.env` con la IP LAN del equipo y puerto 3000, ejecutar `npm run dev:mobile` y abrir el cliente Expo compatible. Después de iniciar sesión, tocar Explorar música. La ruta Expo es `/explorar`, y el detalle `/explorar/cancion/[id]`.

Expo web de revisión se inició en `http://localhost:8087`; usa la API local y ese origen está permitido en CORS. Si se inicia en otro puerto, autorizar el origen correspondiente en la configuración local de NestJS.

## Limitaciones y diferencias

- CU08 no está implementado: reproducción deshabilitada de forma explícita. Favoritos, playlists, historial, álbumes y estadísticas permanecen fuera del bloque.
- Las imágenes de hero y las portadas disponibles no son idénticas a los ejemplos del prototipo. Se reutilizaron recursos existentes; no se copiaron las capturas como interfaz.
- Géneros, cantidades, títulos y portadas dependen de publicaciones reales. Un género sin canciones publicadas no se ofrece como filtro. No se añadieron las ocho canciones sugeridas como contenido ficticio.
- Android físico/emulador queda pendiente para tamaños de texto del dispositivo, teclado, Safe Area y navegación real. La navegación se verificó en Expo web y la compilación Android se verificó por exportación.
- Se detiene el trabajo en CU07 para revisión visual; no se avanzó a CU08.
