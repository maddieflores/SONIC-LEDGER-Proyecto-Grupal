# INFORME TÉCNICO DE IMPLEMENTACIÓN — CU15 + CU16 + CU18
## SONIC LEDGER — SPRINT 3, DÍA 4: Conciertos y Venta de Entradas

---

### 1. Resumen Ejecutivo
Se implementó de manera conjunta y no destructiva la gestión completa de conciertos en Sonic Ledger, cubriendo:
- **CU15 — Crear y configurar concierto**: exclusivo para usuarios con rol `ORGANIZADOR` en la plataforma web.
- **CU16 — Publicar concierto e inicio de venta**: validación de completitud, fechas coherentes, portada segura y cálculo reactivo del estado de venta del lado del servidor.
- **CU18 — Buscar y consultar conciertos**: consulta pública accesible para visitantes no autenticados y usuarios con sesión activa, incorporando el **Ajuste Visual CU18** consistente en un carrusel horizontal de conciertos destacados/próximos estilo Netflix/Spotify con estética neón futurista.

### 3. Migraciones y Base de Datos

Migración ejecutada: `1794490000000-ConciertosEntradas.ts`

```sql
-- Tabla de conciertos
CREATE TABLE conciertos (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  organizador_id uuid NOT NULL REFERENCES usuarios(id) ON DELETE CASCADE,
  titulo varchar(200) NOT NULL,
  descripcion text NOT NULL DEFAULT '',
  portada_url varchar(500) NULL,
  genero varchar(100) NOT NULL DEFAULT '',
  fecha_inicio timestamptz NOT NULL,
  fecha_fin timestamptz NOT NULL,
  zona_horaria varchar(50) NOT NULL DEFAULT 'America/La_Paz',
  recinto varchar(200) NOT NULL,
  direccion varchar(255) NOT NULL,
  ciudad varchar(100) NOT NULL,
  departamento varchar(100) NOT NULL,
  estado varchar(20) NOT NULL DEFAULT 'BORRADOR',
  inicio_venta timestamptz NULL,
  destacado boolean NOT NULL DEFAULT false,
  "createdAt" timestamptz NOT NULL DEFAULT now(),
  "updatedAt" timestamptz NOT NULL DEFAULT now()
);

-- Artistas participantes vinculados
CREATE TABLE concierto_artistas (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  concierto_id uuid NOT NULL REFERENCES conciertos(id) ON DELETE CASCADE,
  artista_id uuid NULL REFERENCES artistas(id) ON DELETE SET NULL,
  nombre_artista varchar(100) NOT NULL,
  orden int NOT NULL DEFAULT 1,
  "createdAt" timestamptz NOT NULL DEFAULT now()
);

-- Categorías de entradas y cupos
CREATE TABLE concierto_categorias (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  concierto_id uuid NOT NULL REFERENCES conciertos(id) ON DELETE CASCADE,
  nombre varchar(100) NOT NULL,
  precio numeric(10, 2) NOT NULL DEFAULT 0,
  moneda varchar(10) NOT NULL DEFAULT 'BOB',
  cupo_total int NOT NULL DEFAULT 0,
  cupo_disponible int NOT NULL DEFAULT 0,
  disponible boolean NOT NULL DEFAULT true,
  "createdAt" timestamptz NOT NULL DEFAULT now(),
  "updatedAt" timestamptz NOT NULL DEFAULT now()
);

-- Índices de consulta
CREATE INDEX conciertos_estado_fecha_idx ON conciertos(estado, fecha_inicio);
CREATE INDEX conciertos_organizador_idx ON conciertos(organizador_id);
CREATE INDEX concierto_artistas_concierto_idx ON concierto_artistas(concierto_id);
CREATE INDEX concierto_categorias_concierto_idx ON concierto_categorias(concierto_id);
```

### 4. Endpoints y Seguridad

| Método | Endpoint | Rol Requerido | Descripción |
|---|---|---|---|
| `GET` | `/api/conciertos` | **Público (Sin sesión)** | Búsqueda y listado paginado de conciertos publicados. Filtros por `q`, `ciudad`, `genero`, `fechaDesde`, `fechaHasta`, `destacados`. No expone borradores ni datos privados. |
| `GET` | `/api/conciertos/artistas-plataforma` | **Público** | Lista artistas registrados para sugerencia y vinculación en eventos. |
| `GET` | `/api/conciertos/:id` | **Público (Sin sesión)** | Detalle público del concierto y sus categorías. Si no está publicado, solo el organizador propietario o admin pueden consultarlo. |
| `GET` | `/api/conciertos/:id/cover/:filename` | **Público** | Servir portada publicitaria con encabezados de caché. |
| `GET` | `/api/conciertos/mis-conciertos` | `ORGANIZADOR` | Listado de conciertos del organizador autenticado. |
| `GET` | `/api/conciertos/organizador/:id` | `ORGANIZADOR` | Consulta de concierto propio con relaciones para edición. |
| `POST` | `/api/conciertos` | `ORGANIZADOR` | Crear nuevo concierto como borrador. |
| `PUT` | `/api/conciertos/:id` | `ORGANIZADOR` | Editar datos de concierto propio (fechas, recinto, descripción, etc.). |
| `POST` | `/api/conciertos/:id/cover` | `ORGANIZADOR` | Subir archivo JPG/PNG de portada (máx. 5 MB) con validación estricta. |
| `POST` | `/api/conciertos/:id/categorias` | `ORGANIZADOR` | Agregar categoría de entrada (moneda BOB, precio >= 0, cupo > 0). |
| `PUT` | `/api/conciertos/:id/categorias/:catId` | `ORGANIZADOR` | Modificar categoría existente de concierto propio. |
| `DELETE` | `/api/conciertos/:id/categorias/:catId` | `ORGANIZADOR` | Eliminar categoría de entrada. |
| `POST` | `/api/conciertos/:id/artistas` | `ORGANIZADOR` | Asociar artista (de la plataforma o manual) con orden. |
| `DELETE` | `/api/conciertos/:id/artistas/:relId` | `ORGANIZADOR` | Quitar artista participante. |
| `POST` | `/api/conciertos/:id/publicar` | `ORGANIZADOR` | Publicar concierto tras validar completitud (CU16). |

#### Lógica del Estado de Venta del Servidor
El estado de venta se calcula de manera dinámica en el backend (`computeSalesStatus`) a partir de la fecha y hora actual (`now`), la fecha de inicio de venta (`inicioVenta`) y la fecha de finalización (`fechaFin`):
- `VENTA_NO_INICIADA`: Concierto en estado `BORRADOR` o `CANCELADO`.
- `VENTA_PENDIENTE`: Concierto `PUBLICADO` y `now < inicioVenta` ("Venta próximamente").
- `VENTA_INICIADA`: Concierto `PUBLICADO`, `now >= inicioVenta` y `now <= fechaFin` ("Venta disponible").
- `VENTA_CERRADA`: Concierto `PUBLICADO` y `now > fechaFin` ("Venta cerrada").

### 6. Pruebas y Verificación

La suite de pruebas automatizadas en Vitest incluye 18 tests dirigidos en `backend/src/conciertos/conciertos.spec.ts`:
1. Creación de borrador como `ORGANIZADOR` con datos válidos.
2. Rechazo de fechas incoherentes (`fechaInicio >= fechaFin`).
3. Rechazo de modificación de conciertos ajenos por otro organizador (`ForbiddenException`).
4. Configuración de categorías de entrada con precios en `BOB` y cupos positivos.
5. Rechazo de categorías con precios negativos o cupos `<= 0`.
6. Rechazo de nombres duplicados de categoría dentro del mismo concierto.
7. Rechazo de publicación sin portada publicitaria.
8. Rechazo de publicación sin al menos una categoría de entradas.
9. Rechazo de publicación de eventos con fecha en el pasado.
10. Publicación exitosa de concierto completo con cálculo de `estadoVenta: VENTA_INICIADA`.
11. Verificación de cálculo reactivo `VENTA_PENDIENTE` si `inicioVenta` es futuro.
12. Verificación de cálculo reactivo `VENTA_CERRADA` si la fecha del concierto ya expiró.
13. Ocultamiento de conciertos en borrador del catálogo público.
14. Consulta de conciertos publicados por visitantes sin token / sin sesión.
15. Protección contra exposición de datos privados del usuario organizador en respuestas públicas.
16. Denegación de acceso público a detalles de borradores.
17. Permiso del organizador propietario para consultar sus propios borradores.
18. Comprobación del `RolesGuard`: rechazo a usuarios con solo rol `CLIENTE` y admisión a usuarios con rol `ORGANIZADOR`.

### 7. Confirmación de Lectura Pública y Permisos

- **Confirmación de lectura pública sin sesión**: Los endpoints `GET /api/conciertos` y `GET /api/conciertos/:id` no tienen guardias de autenticación obligatorias (`JwtGuard` no es exigido). Tanto en la web (`/conciertos`) como en la aplicación móvil, los visitantes que no han iniciado sesión pueden buscar, filtrar y consultar cualquier concierto publicado y sus categorías de entrada con total libertad.
- **Confirmación de permisos del organizador**: Todas las rutas de administración (`POST /api/conciertos`, `PUT /api/conciertos/:id`, `POST /api/conciertos/:id/cover`, categorías, artistas y `POST /api/conciertos/:id/publicar`) exigen `JwtGuard` y `RolesGuard` con `@Roles(RolNombre.ORGANIZADOR)`. Adicionalmente, el servicio valida rigurosamente que `concierto.organizadorId === user.id`, impidiendo que un organizador modifique eventos creados por otro organizador. Un usuario con solo rol `CLIENTE` recibe `ForbiddenException (403)` si intenta crear o modificar conciertos.
