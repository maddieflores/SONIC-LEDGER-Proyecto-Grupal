# INFORME TÉCNICO DE IMPLEMENTACIÓN — CU12
## SONIC LEDGER — SPRINT 2, BLOQUE 1: Recomendaciones Musicales Personalizadas

---

### 1. Resumen Ejecutivo

En este bloque se diseñó e implementó de manera completa y desacoplada el caso de uso **CU12 — Obtener recomendaciones musicales personalizadas**.
El sistema analiza información musical verídica del usuario (preferencias de género de CU03, favoritos de CU10 e historial de reproducciones válidas y omisiones de CU11/CU23) para producir un ranking determinista, explicable y de alta afinidad sobre las pistas disponibles en el catálogo híbrido de Sonic Ledger (`LOCAL` y `AUDIUS`).

El motor es ligero, computacionalmente eficiente y opera sin requerir GPU ni servicios externos de pago, ejecutándose de forma óptima en entornos de desarrollo locales (laptop Ryzen 7 con 16 GB RAM). Además, incluye el contrato de selección musical `ITrackSelector`, el cual servirá como base directa para la futura integración del DJ con IA local (CU13 y CU14).

---

### 2. Algoritmo y Motor de Recomendaciones

#### 2.1. Naturaleza del Algoritmo
El algoritmo implementado es un **sistema de recomendación determinista basado en contenido y afinidad multi-señal (Content-Based Filtering)**.

> [!NOTE]
> **Aclaración de Transparencia Técnica:** No se entrenó un modelo de redes neuronales ni machine learning pesado en esta fase. Se empleó un sistema de reglas deterministas, funciones de ponderación lineal acotadas y análisis de señales de consumo musical real.

#### 2.2. Señales Utilizadas y Ponderación

El puntaje de afinidad se calcula de 0 a 100 puntos evaluando las siguientes señales reales:

| Señal Musical | Caso de Uso | Puntos / Impacto | Criterio de Activación |
|---|:---:|:---:|---|
| **Género Preferido** | CU03 | **+30 pts** | El género de la pista coincide con uno de los géneros declarados en `musicPreferences.genreIds`. |
| **Canción en Favoritos** | CU10 | **+25 pts** | La canción específica está guardada en los favoritos del usuario (`favorite_tracks`). |
| **Artista en Favoritos** | CU10 | **+20 pts** | El artista de la canción tiene canciones añadidas en los favoritos del usuario. |
| **Artista en Historial Válido** | CU11 / CU23 | **+15 pts** | El usuario ha reproducido canciones de este artista con evento `PLAYED` y `listened_seconds > 0`. |
| **Artista Frecuente** | CU11 / CU23 | **+10 pts** | El usuario ha reproducido canciones del artista 3 o más veces. |
| **Tiempo Escuchado Efectivo** | CU11 / CU23 | **+10 pts** | Tiempo acumulado escuchado del artista $\ge 120$ segundos (2 minutos). |
| **Género Frecuente en Historial** | CU11 / CU23 | **+10 pts** | El género ha sido reproducido al menos 2 veces en el historial reciente. |
| **Afinidad Complementaria** | Catálogo | **+10 pts** | Canción elegible de descubrimiento para completar la cuota si no hay coincidencias directas. |
| **Penalización por Omisión (SKIPPED)** | CU11 | **-30 pts** | La pista fue omitida (`SKIPPED`) por el usuario; la penalización reduce drásticamente su prioridad. |

El puntaje total se normaliza y acota en el rango $[0, 100]$.

#### 2.3. Explicabilidad y Motivos Verificables (`motivosRecomendacion`)
Cada recomendación contiene razones humanas legibles y verificables generadas a partir de las señales disparadas:
- *"Porque te gusta el género [Rock]"*
- *"Está en tu lista de canciones favoritas"*
- *"Por artistas en tus favoritos: [Nombre del Artista]"*
- *"Has escuchado a [Nombre del Artista]"*
- *"Artista frecuente en tu historial (X reproducciones)"*
- *"Más de X min escuchados de este artista"*
- *"Género frecuente en tu historial reciente"*

#### 2.4. Filtros de Seguridad, Negocio y Diversidad
1. **Exclusión de Canciones No Reproducibles**: Únicamente se evalúan y recomiendan canciones con archivo de audio válido y disponible (`playable === true`). Se descartan pistas en borrador o sin stream accesible.
2. **Diversidad Artística (`maxPorArtista`)**: Se limita a un máximo de 2 canciones por artista en la lista de recomendaciones para evitar monopolizar el carrusel con un único creador.
3. **Manejo de Cold Start (Usuarios sin historial)**:
   - Si el usuario no tiene preferencias, favoritos ni reproducciones, el motor devuelve una selección de descubrimiento general del catálogo con diversidad de artistas.
   - La respuesta se marca con `esPersonalizada: false`.
   - Se asigna un puntaje base de 50 y se incluye el motivo: *"Descubrimiento general en Sonic Ledger. ¡Personaliza tu perfil o escucha canciones para recomendaciones a tu medida!"*.

### 3. Arquitectura y Preparación para el DJ (CU13 y CU14)

#### 3.1. Interfaz Desacoplada `IMusicRecommender`
El servicio `MusicRecommendationsService` implementa `IMusicRecommender`:
```typescript
export interface IMusicRecommender {
  getRecommendations(
    userId: string,
    limit?: number,
  ): Promise<MusicRecommendationsResponse>;
}
```
Esto permite sustituir la lógica interna o conectarla mediante HTTP/gRPC a un microservicio en Python (FastAPI / Ollama / Liquid AI) sin modificar controladores ni clientes web y móvil.

#### 3.2. Contrato de Selección Musical `ITrackSelector`
Para abastecer las futuras necesidades del DJ interactivo con IA (CU13 y CU14), se creó el servicio `TrackSelectorService` que implementa:
```typescript
export interface TrackSelectorConstraints {
  generos?: string[];
  artistasExcluidos?: string[];
  cancionesExcluidas?: string[];
  duracionMinimaSegundos?: number;
  duracionMaximaSegundos?: number;
  soloPlayable?: boolean;
  maxPorArtista?: number;
  limite?: number;
}

export interface ITrackSelector {
  selectTracks(
    candidates: CandidateTrack[],
    constraints: TrackSelectorConstraints,
  ): CandidateTrack[];
}
```
Garantías del selector:
- Valida estrictamente que las canciones seleccionadas provengan del conjunto de candidatas reales.
- Nunca inventa títulos, artistas ni identificadores.
- Aplica filtros de duración y exclusión de canciones ya sonadas.

### 4. Endpoints de la API

Los endpoints se encuentran protegidos mediante `JwtGuard` bajo el prefijo `/api/auth/recommendations`:

1. **`GET /api/auth/recommendations/music`** (y alias `GET /api/auth/recommendations`)
   - **Query Params**: `limit` (opcional, default 10, máx 30).
   - **Autenticación**: `Bearer <token>` o cookie HttpOnly de sesión.
   - **Respuesta (200 OK)**:
     ```json
     {
       "items": [
         {
           "id": "c1f7b09e-3151-4034-8c81-8b2b71c4c1a0",
           "source": "LOCAL",
           "titulo": "Furia Andina",
           "artista": { "id": "a9d8c2...", "nombre": "Illimani Rock" },
           "genero": { "id": "g-rock", "nombre": "Rock" },
           "duracionSegundos": 210,
           "coverUrl": "/api/auth/catalog/c1f7b09e.../cover",
           "score": 85,
           "motivosRecomendacion": [
             "Porque te gusta el género Rock",
             "Has escuchado a Illimani Rock"
           ],
           "playable": true
         }
       ],
       "total": 10,
       "esPersonalizada": true,
       "criterioPrincipal": "Afinidad por preferencias, favoritos e historial de escucha"
     }
     ```

2. **`POST /api/auth/recommendations/select-tracks`**
   - **Body**: `{ candidates: CandidateTrack[], constraints: TrackSelectorConstraints }`
   - **Respuesta (200 OK)**: `{ selected: CandidateTrack[] }`

### 6. Verificación y Resultados de Pruebas

Se diseñó la suite `backend/src/recommendations/cu12-recomendaciones.spec.ts` verificando los 10 puntos de control exigidos:

1. **Dos usuarios con gustos diferentes obtienen rankings diferentes**: Un usuario afín al Rock recibe canciones de Rock con score alto, mientras que un usuario afín al Pop recibe canciones de Pop como primer resultado.
2. **Cambiar favoritos modifica el ranking**: Añadir una pista a favoritos incrementa el puntaje de afinidad e incluye el motivo correspondiente.
3. **Cambiar preferencias influye en las recomendaciones**: Modificar `genreIds` altera las prioridades del ranking y actualiza las explicaciones.
4. **El historial válido influye en el resultado**: Reproducciones completas y tiempo efectivo escuchado ($\ge 120$ s) incrementan el puntaje y activan reconocimientos de artista frecuente.
5. **SKIPPED no equivale a reproducción completa**: El evento `SKIPPED` no suma puntos de tiempo efectivo y aplica una penalización de 30 puntos al score de la canción.
6. **Se respetan los identificadores LOCAL y AUDIUS**: Se preservan los prefijos y formatos sin alteración.
7. **No se inventan canciones ni artistas**: Cada recomendación devuelta existe en la base de datos o en la respuesta de Audius.
8. **No se recomiendan canciones inaccesibles**: Canciones sin archivo de audio o con `playable === false` son excluidas.
9. **Gestión de Cold Start**: Usuarios sin historial ni preferencias son atendidos con descubrimiento general, `esPersonalizada: false` y score neutral.
10. **Contrato de selección para DJ**: `TrackSelectorService` respeta restricciones de géneros, duraciones, no reproducibles y cuotas máximas por artista.

#### Resumen de Ejecución:
- **Pruebas específicas CU12**: 10 pasadas de 10 (22 ms).

### 7. Limitaciones por Metadatos Incompletos

1. **BPM y Métricas Acústicas**: El catálogo actual no almacena información de BPM, tonalidad o valencia acústica en la entidad `canciones`. Por tanto, el motor no inventa estos valores y basa la similitud en metadatos reales verificables (géneros, artistas, duraciones y frecuencias de escucha).
2. **Conexión Externa a Audius**: Si la API de Audius presenta latencia o indisponibilidad temporal, el motor continúa operando con el catálogo local y degrada el servicio sin interrumpir las recomendaciones.

Para la posterior integración del microservicio de IA local (Sprint 2: Python / FastAPI / Liquid AI / Ollama):
