# CU08 — Reproducir música

Implementación de reproducción real para web y aplicación Expo/Android, conectada al catálogo publicado. Inicio y la administración artística conservan sus rutas y composición. No se implementaron CU06, CU09, CU10 ni CU11.

## Archivos y componentes

- Backend: `src/catalog/catalog.controller.ts`, `catalog.service.ts`, `catalog.module.ts`, `audio-range.ts` y `audio-range.spec.ts`. Streaming autenticado y lectura del perfil público del artista. Scripts de comprobación: `scripts/verify-cu08.mjs`, `prepare-cu08-queue.mjs` y `cleanup-cu08-queue.mjs`.
- Compartido: `shared/catalog.ts` incorpora `playable`; `shared/playback.ts` define cola, repetición, aleatorio, tiempos y contrato del artista público.
- Web: `frontend/src/PlaybackContext.ts`, `Playback.tsx`, `Playback.css`, `PublicArtist.tsx`. Integración mínima en `App.tsx` y `Catalog.tsx`. El recurso decorativo existente se reutiliza en `frontend/public/images/sonic-artist-hero.png`.
- Móvil: `mobile/src/features/playback/NativePlayback.tsx`, `src/app/reproduciendo.tsx`, `src/components/CatalogIcon.tsx`. Integración en `src/app/_layout.tsx` y `src/features/catalog/CatalogScreen.tsx`; configuración de audio en `mobile/app.json`.

Web centraliza un único HTMLAudioElement en PlayerProvider; Expo centraliza un único useAudioPlayer en NativePlayerProvider. FullPlayer, MiniPlayer, controles, portada, onda y cola comparten ese motor. Navegar no crea un reproductor adicional. Cerrar la sesión libera la fuente. Pausa, duración, posición y finalización proceden de los eventos reales del audio. La onda es decorativa y su progreso/búsqueda sí controlan el audio real.

## API y seguridad

Todos los contratos requieren la sesión existente:

| Método y ruta | Resultado |
| --- | --- |
| GET/HEAD `/api/auth/catalog/:id/audio` | WAV PCM publicado; 200 completo, 206 rango simple, 416 rango inválido |
| GET `/api/auth/catalog/artists/:id` | Perfil público real, canciones publicadas paginadas y último lanzamiento publicado asociado, si existe |
| GET `/api/auth/catalog/artists/:id/media/:kind` | Avatar o portada pública del perfil; `kind` es avatar o cover |

El streaming responde Content-Type, Content-Length, Accept-Ranges y Content-Range cuando corresponde. Solo acepta archivos locales canónicos de CU05 y UUID válidos; no permite rutas arbitrarias. Primero comprueba publicación y después abre el archivo. Borradores devuelven 404, incluso solicitando Range. Sin sesión devuelve 401. Las operaciones privadas del artista siguen protegidas por rol y propiedad; CLIENTE recibe 403.

Web usa la cookie HttpOnly; Android usa el encabezado Bearer. Nunca se introducen credenciales en URLs. La variante Expo web descarga un blob autenticado y revoca su URL al cambiar/cerrar; no equivale al streaming progresivo de Android. Caché privada/no-store. No hay migraciones ni cambios al modelo de datos.

## Visualización

Desde la raíz:

```powershell
npm run dev:backend
npm run dev:frontend
npm run dev:mobile
```

En web, entrar a `/explorar`, reproducir una canción y abrir su detalle. El nombre del artista conduce a `/artistas/:id`, una vista pública independiente del panel de administración. La portada del minirreproductor abre `/reproduciendo`. En móvil, reproducir desde Explorar abre `/reproduciendo`; regresar conserva audio y muestra el mini encima de la navegación inferior.

Para Android físico, EXPO_PUBLIC_API_URL debe apuntar a la IP LAN del equipo y puerto 3000, con sufijo `/api`, nunca al localhost del teléfono. La configuración móvil existente usa la dirección LAN; comprobar que siga siendo la IP actual y que el teléfono alcance el backend. Los cambios de configuración nativa requieren reconstruir el cliente de desarrollo si corresponde.

## Verificación realizada

- Backend y web: build y lint correctos; móvil: TypeScript y lint correctos.
- Vitest: 9 archivos y 31 pruebas aprobadas. Las pruebas HTTP requieren conexiones locales fuera del sandbox restringido.
- API real: bytes RIFF/WAVE; 200, 206, 416, HEAD, Content-Length/Range; 401 sin sesión, 404 en borradores, perfil sin email/identificadores privados/verificación ficticia.
- Navegador web: WAV real, pausa/reanudación, seek, cambio anterior/siguiente, finalización, repetir uno, aleatorio y cola. Misma instancia de audio entre catálogo, detalle, artista y reproductor completo.
- Expo web con expo-audio: WAV real, progreso, pausa, seek, cola y minirreproductor persistente, una sola instancia audible.
- Fallo de conexión: mensaje de error, reintento reproduce audio real; salir a autenticación detiene/libera la fuente.
- Regresión CU07: búsqueda por título/artista/género, filtros, paginación, detalle y portadas publicados; borradores ocultos. Regresión CU05: cliente sin acceso a administración artística.
- `npx expo export --platform android --output-dir ../tmp/cu08-android`: bundle Hermes generado, 1174 módulos. Esta exportación no es una compilación de APK ni una ejecución en dispositivo Android.

Para verificar dos pistas se creó un registro técnico nuevo copiando los bytes de un WAV real ya publicado. Al terminar se devolvió ese registro a borrador y se comprobó que ni su detalle ni su audio son accesibles para CLIENTE. No se eliminaron registros ni se modificaron canciones históricas. Los scripts de cola requieren el fixture local ignorado en `tmp`; la limpieza se ejecuta antes de regenerarlo con verify-cu08.

Capturas de la revisión: `tmp/cu08-public-artist-web.png`, `tmp/cu08-full-web.png`, `tmp/cu08-mobile-full.png` y `tmp/cu08-mobile-mini.png`. La captura del perfil se tomó durante la prueba con dos pistas; la publicación técnica ya fue retirada.

## Diferencias y límites

- Se respeta la composición de las referencias: sidebar, hero público, canciones compactas y barra fija en web; portada circular, onda, controles centrales y cola en móvil. Portadas y nombres proceden de los datos reales y pueden diferir de las ilustraciones; sin portada se muestra un placeholder.
- Se omiten cifras de reproducciones, oyentes y verificación. Favoritos y secciones futuras se muestran deshabilitados o vacíos, sin simular éxito.
- Canciones históricas sin WAV local compatible aparecen con audio no disponible. No se sustituyen por archivos de muestra.
- Reproducción en primer plano: Android pausa al pasar a segundo plano. No se habilitaron servicio en segundo plano, notificaciones multimedia ni controles de pantalla bloqueada; tampoco permiso de micrófono o grabación.
- Pendiente de revisión final del sprint: build nativa APK y reproducción en Android físico, con conectividad LAN y WAV PCM de producción. La validación ejecutada de expo-audio fue en Expo web, además de la exportación Android.
