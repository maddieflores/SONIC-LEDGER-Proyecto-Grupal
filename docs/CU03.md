# CU03 — Perfil y preferencias musicales

Implementación sobre CU01/CU02; no se alteraron onboarding, registro ni login.

## Archivos

- `backend/src/auth/profile.controller.ts`, `profile.dto.ts`, `profile.service.ts`, `profile.spec.ts`: endpoints protegidos, validación, persistencia y pruebas.
- `backend/src/auth/usuario.entity.ts`, `auth.module.ts`, `backend/src/data-source.ts`: columnas de perfil y registro del módulo/migraciones.
- `backend/src/migrations/1794483000000-PerfilPreferencias.ts`: nombre visible, biografía y preferencias JSONB por usuario.
- `backend/src/migrations/1794484000000-GenerosPerfil.ts`: agrega Pop, Rock, Electrónica, Indie y Reguetón, respetando el índice normalizado y los datos existentes.
- `frontend/src/Profile.tsx`, `Profile.css`, `App.tsx`: interfaz responsive y rutas `/inicio` y `/perfil`.
- `mobile/src/app/perfil.tsx`, `inicio.tsx`, `mobile/metro.config.js`: pantalla nativa, acceso desde inicio y resolución de código compartido.
- `shared/profile.ts`: contratos y funciones puras compartidos por web y móvil.
- `tmp/verify-cu03.cjs`, `tmp/verify-cu03-mobile.cjs`: verificaciones de integración reproducibles en este entorno.

Ambas migraciones fueron aplicadas en PostgreSQL local. No se eliminó ningún dato. Su reversión automática está deshabilitada para evitar pérdida de información.

## API

Todos los endpoints requieren la sesión existente: cookie HttpOnly web o Bearer móvil.

- `GET /api/auth/profile`: perfil y preferencias propios.
- `POST /api/auth/profile`: guarda `displayName`, `biography`, `genreIds`, `moods`, `intensity`, `discovery`, `energy`.
- `GET /api/auth/profile/genres`: géneros activos de PostgreSQL.

No hay parámetro para elegir otra cuenta. El id procede exclusivamente de JwtGuard. Se rechazan campos extra, roles, email, username, ids ajenos, géneros desconocidos/inactivos, estados de ánimo no admitidos y porcentajes fuera de 0–100. Nombre visible: 2–60 caracteres tras recortar espacios. Biografía: máximo 300 caracteres. Usuario y correo son de solo lectura. No se gestionan contraseñas en CU03.

Las preferencias musicales se guardan juntas de forma atómica en JSONB. Los géneros se validan contra el catálogo activo al guardar. Los valores iniciales de los tres ajustes son 50%; no representan una inferencia de IA.

## Cómo abrir

1. PostgreSQL: `docker compose --env-file database/.env -f database/compose.yaml up -d --wait postgres`.
2. Backend: `npm --prefix backend run migration:run` y `npm run dev:backend` (API local puerto 3000).
3. Web: `npm run dev:frontend`; abrir `http://localhost:5173/perfil` e iniciar sesión. `/inicio` también abre CU03.
4. Android: configurar `EXPO_PUBLIC_API_URL` en `mobile/.env` con la IP LAN de esta computadora y puerto 3000; iniciar `npm run dev:mobile`, abrir el cliente Expo compatible y entrar a **Mi perfil y preferencias** desde Inicio. Usar **Recordarme** para conservar el token en SecureStore al reiniciar (la sesión JWT mantiene su vencimiento existente de una hora).

## Diferencias y dependencias explícitas

Se conservaron composición, paleta, dos paneles web, sidebar, chips y sliders. La onda se construyó con SVG en web y decoración nativa en móvil. El personaje de la sidebar usa el recurso existente de Sonic Ledger; no es idéntico al personaje de referencia. Los avatares usan un símbolo/inicial del usuario: no hay infraestructura segura de almacenamiento ni avatar persistido y el botón de cámara lo explica. No se simulan subidas.

El catálogo de artistas existe, pero todavía no tiene selección/persistencia de favoritos; móvil muestra una sección informativa sin artistas ficticios. La biografía admite 300 caracteres frente a los 160 del prototipo. Móvil agrega ajustes con controles nativos +/− y barra de porcentaje, más abajo del contenido de referencia. No hay algoritmo de recomendaciones. Navegaciones de módulos futuros informan su indisponibilidad. No se implementaron CU04/CU05.
