## Endpoints

Todos exigen autenticación y el rol ARTISTA. El usuario se obtiene de la sesión validada, nunca del cuerpo ni de un id proporcionado por el cliente.

| Método | Ruta | Función |
|---|---|---|
| GET | `/api/auth/artist-profile` | Perfil artístico propio; `profile: null` si aún no existe |
| POST | `/api/auth/artist-profile` | Crear el perfil propio; 409 si ya existe |
| PATCH | `/api/auth/artist-profile` | Editar el perfil propio; 404 si aún no existe |
| POST | `/api/auth/artist-profile/media/avatar` | Cargar y asociar avatar real |
| POST | `/api/auth/artist-profile/media/cover` | Cargar y asociar portada real |
| GET | `/api/auth/artist-profile/media/:name` | Leer exclusivamente una imagen actualmente asociada al perfil propio |

Se reutiliza `GET /api/auth/profile/genres` de CU03 para consultar el catálogo activo.

El formulario guarda nombre artístico, biografía, ciudad, país, géneros existentes, etiquetas de identidad y enlaces. Usuario es de solo lectura. Los atributos `id`, `usuarioId`, roles, avatarUrl y coverUrl no se aceptan en el formulario. Las referencias de imágenes se asignan exclusivamente después de almacenar un archivo autorizado.

CLIENTE por sí solo recibe 403 en lectura y escritura, incluyendo cargas. ADMIN sin ARTISTA tampoco obtiene acceso de escritura: se respeta el permiso requerido sin excepciones implícitas. La pantalla explica que la habilitación necesita autorización. No hay endpoint de autoasignación de ARTISTA ni se modificó el registro público.

## Validación y persistencia

- Nombre artístico: 2–100 caracteres, espacios exteriores recortados. Se mantiene el índice único existente sobre `lower(trim(nombre_artistico))`.
- Biografía: máximo 500 caracteres, conservando biografías previas.
- Ciudad y país: máximo 80 caracteres cada uno.
- Hasta 20 géneros activos, sin duplicados, asociados mediante `artistas_generos` y claves foráneas.
- Identidad: selección explícita entre las etiquetas ofrecidas; sin algoritmos de IA.
- Enlaces HTTPS, máximo 500 caracteres. Instagram, TikTok, YouTube y Spotify deben corresponder al dominio de esa red. No se admiten credenciales en URLs ni esquemas ejecutables.
- El nombre, las redes, identidad y relaciones de géneros se guardan mediante TypeORM; `synchronize: false` permanece intacto.

Se aplicó `PerfilArtistico1794485000000`: columnas `cover_url`, `ciudad`, `pais`, `identidad`, `redes`, y tabla `artistas_generos` con sus restricciones. No se eliminaron ni se reescribieron registros existentes. La reversión automática está deshabilitada para no perder perfiles.

La comparación directa de la fila de Aura Neón antes y después de la integración confirmó su conservación completa. Su URL de avatar de demostración, del dominio de ejemplo no configurado, se conserva en PostgreSQL; la interfaz ofrece un avatar inicial hasta cargar una imagen local real, sin simular una descarga válida.

## Imágenes locales de desarrollo

- Se guardan realmente en `backend/uploads/artists/` cuando Nest se inicia desde backend.
- PNG o JPEG de hasta 2 MiB, 4096 px por lado y 8 megapíxeles.
- Se comprueban firma binaria y dimensiones; PNG también comprueba estructura, CRC e información comprimida con límite de descompresión. Se rechazan SVG, PNG animados, tipos falsificados y archivos corruptos detectados por esas validaciones.
- Los nombres los genera el servidor con UUID. Se escribe con exclusión (`wx`), sin sobrescribir archivos y sin usar el nombre/ruta del cliente.
- La lectura comprueba formato del nombre y propiedad de la referencia. Las imágenes no se publican mediante una carpeta estática; no se puede leer la imagen de otra cuenta.
- Respuestas con MIME fijo, `nosniff` y caché privada deshabilitada. Expo web recupera los bytes mediante Bearer y una URL blob temporal; Android utiliza encabezados de autorización en Image.
- En producción, las cargas locales devuelven 403. Para producción se necesitará almacenamiento persistente apropiado; esta solución es deliberadamente local.
- Si falla la asociación en PostgreSQL, se elimina únicamente el archivo recién creado. Los archivos sustituidos permanecen en desarrollo para evitar borrados de datos existentes; su limpieza y cuotas de almacenamiento serán una operación de infraestructura separada.

## Cómo abrir

**Web:** iniciar PostgreSQL, ejecutar `npm --prefix backend run migration:run`, `npm run dev:backend` y `npm run dev:frontend`. Abrir `http://localhost:5173/perfil-artistico` e iniciar sesión con una cuenta ARTISTA, por ejemplo `demo.artista@example.com` con la contraseña demo ya configurada. También hay un enlace Perfil artístico desde Inicio/Mi perfil. Un cliente verá la explicación de habilitación y no el formulario.

**Android:** configurar `EXPO_PUBLIC_API_URL` de `mobile/.env` con la IP LAN del equipo y puerto 3000. Ejecutar `npm run dev:mobile`, abrir el cliente Expo compatible e iniciar sesión con ARTISTA. Desde Inicio, entrar en Perfil artístico. Las cargas usan la galería; los permisos de la configuración requieren reconstruir el cliente si su compilación anterior no contiene la configuración actualizada de image-picker.

**Vista Expo web de revisión:** `http://localhost:8086/perfil-artistico`. La API de la sesión de revisión se inició autorizando los orígenes locales 5173/5174/8085/8086. Al reiniciar con la configuración habitual, añadir el origen de Expo web a `CORS_ORIGINS` para usar esta vista. No se modificó permanentemente `.env`.

Pendiente en Android físico/emulador: interacción con galería nativa, teclado, Safe Area, regreso del segundo plano, reinicio completo y recuperación del token recordado. La compilación y la navegación se verificaron con las herramientas disponibles; no se afirma una prueba física.

## Diferencias frente al prototipo

Se conserva la composición web de portada panorámica, avatar superpuesto, navegación, dos columnas y tarjetas, y el formulario vertical móvil con portada al final. La ciudad predeterminada es una ilustración construida con componentes/CSS, más sencilla que la imagen artística del prototipo; falta el recurso panorámico original. El avatar usa una inicial cuando no hay imagen real: no se asocia un personaje ficticio a la cuenta. La decoración lateral reutiliza un recurso existente de Sonic Ledger.

Las estadísticas muestran No disponible, sin cifras ni insignias de verificación inventadas. La biografía admite 500 caracteres frente a los 160 representados en la captura; las ubicaciones se editan mediante dos campos, sin un catálogo geográfico inexistente. La identidad en móvil se despliega para conservar la jerarquía de la referencia. Las imágenes no son públicas y solo la cuenta propietaria puede consultarlas en CU04.

No se avanzó a CU05.
